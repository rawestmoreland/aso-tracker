# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

ASO (App Store Optimization) keyword rank tracker. A daily job searches the iTunes Search API for each tracked keyword and records where each tracked app (yours and competitors) ranks. Two independent parts:

- `backend/` — Go, built on PocketBase (embedded SQLite, admin UI, REST API, cron). Module name `aso-tracker`.
- `frontend/` — TanStack Start (React 19, TanStack Router/Query/Table, Tailwind 4, Recharts) deployed to Cloudflare Workers. Reads data from PocketBase via the `pocketbase` JS SDK.

## Commands

Backend (run from `backend/`):
- `make run` — `go run . serve --http localhost:8080` (PocketBase dashboard at `/_/`)
- `go test ./...` — all tests; single test: `go test ./internal/itunes -run TestName`
- Migrations in `backend/migrations/` are auto-generated when collections are changed in the dashboard while running via `go run` (`Automigrate` is enabled only when `IsProbablyGoRun`). Commit the generated files.

Frontend (run from `frontend/`):
- `npm run dev` (port 3000), `npm run build`, `npm run deploy` (build + `wrangler deploy`)
- `npm run check` / `lint` / `format` — Biome (not ESLint/Prettier)
- No test runner is configured.
- `src/routeTree.gen.ts` is generated by the router plugin during `vite build`/`dev`; don't hand-edit.
- Add shadcn components with `pnpm dlx shadcn@latest add <component>` (see `frontend/.cursorrules`).
- `src/lib/pocketbase-types.ts` is generated PocketBase typings (collection record types).
- PocketBase URL comes from `PB_URL` env (default `http://localhost:8080`).

## Backend architecture

- `main.go` wires everything: PocketBase app, the `rankCheck` cron (`ASO_CRON`, default `0 2 * * *`, UTC), and two superuser-only routes:
  - `POST /api/aso/check-now` — starts a run in a goroutine, returns 202.
  - `POST /api/aso/import-keywords?country=us` — body is a keyword file (see `keywords.Parse`); skips existing `term`+`country` pairs. `api.http` has sample requests (it contains live credentials — don't copy or propagate them).
- `internal/tracker.Runner` — worker pool over all `tracked` keywords. One iTunes search per keyword; from that single response it writes a `rank_history` row for **every** tracked app (rank from `itunes.RankOf`). One DB transaction per keyword. An atomic flag prevents overlapping runs (`ErrAlreadyRunning`).
- `internal/itunes` — Search API client plus a shared `Limiter` that spaces requests across all workers and can back off at runtime when the API refuses requests. Tune with `ASO_INTERVAL` (default 3s) and `ASO_WORKERS` (default 3).
- Collections: `keywords` (term, country, tracked), `tracked_apps` (track_id), `rank_history` (keyword, app, rank, append-only), and `latest_ranks` — a **view collection** over `rank_history` (latest rank, 7-day rank, first rank per keyword/app) defined in a migration, which is what the frontend mostly reads.
- Deploy: `backend/Dockerfile` builds a static binary (pure-Go SQLite, `CGO_ENABLED=0`) and serves on `:8080`. `pb_data/` is runtime data (persist it as a volume).

## Frontend notes

File-based routes live in `src/routes/`; `__root.tsx` is the layout. TanStack Query is provided via `src/integrations/tanstack-query/`. The `#/*` import alias maps to `src/*` (package.json `imports`).
